# Context Window and API Costing

Context window and API costing are two important practical constraints when working with large language models.

The context window controls how much text the model can consider at once.

API costing controls how much you pay when using a model through an API.

# Context Window

The **context window** is the maximum number of tokens a model can fit into one request.

It includes the text the model can look back on when generating the next token.

If the input is larger than the model's context window, the request fails or must be shortened.

# What Fits Inside the Context Window

The context window is not only the latest user message.

It includes:

- Earlier user messages.
- Earlier assistant replies.
- System or developer instructions.
- Retrieved documents or RAG content.
- Examples used in prompting.
- The new message being sent.
- The generated output tokens, except the final token currently being predicted.

This means a conversation grows over time. As it grows, more of the context window is used.

# Why Context Window Matters

The context window limits how much background information the model can use.

If important information is outside the context window, the model cannot directly use it for the next prediction.

Large context windows are useful for:

- Long conversations.
- Large documents.
- Multi-shot prompting.
- RAG systems.
- Code assistants.
- Questions over large books or reports.

# Multi-Shot Prompting

Multi-shot prompting means giving the model several example inputs and outputs before asking it to answer a new question.

These examples help the model understand the pattern it should follow.

But the examples take up space inside the context window.

# RAG and Context Window

RAG stands for **Retrieval-Augmented Generation**.

In RAG, relevant information is retrieved from external documents and inserted into the prompt.

This helps the model answer using external knowledge, but the retrieved text also consumes context-window space.

# API Costs

Chat products such as ChatGPT usually use subscriptions or usage limits.

APIs are different.

When using an API, you usually pay per use, based on the number of tokens processed.

API costs help pay for inference compute, because the model performs many calculations to generate an answer.

# Input Tokens

Input tokens are the tokens sent into the model.

They include the full conversation or prompt sequence being passed in, not only the newest message.

Input tokens may include:

- Chat history.
- System prompts.
- User messages.
- Tool results.
- RAG documents.
- Multi-shot examples.

Longer inputs usually cost more.

# Output Tokens

Output tokens are the tokens generated by the model.

Longer answers usually cost more.

For reasoning models, output-token costs may also include hidden reasoning tokens that are generated internally.

Sometimes these reasoning tokens are not shown to the user, but they still require compute and may still count toward cost.

# Cost Formula

A simple way to think about API cost is:

`total_cost = input_token_cost + output_token_cost`

More explicitly:

`total_cost = input_tokens * input_price + output_tokens * output_price`

In practice, prices are usually listed per million tokens.

Output tokens often cost more than input tokens.

# Example Cost Intuition

If a model costs a few dollars per million tokens, then a very small request with only a few tokens costs a tiny fraction of a dollar.

For personal experiments and short prompts, the cost of each individual API call is usually very small.

For products with many users, long conversations, or agent loops, token usage can grow quickly and must be planned carefully.

# Agent Loops and Cost

Agent loops can become expensive because the model may call itself many times.

Each step can include:

- Previous conversation.
- Tool outputs.
- Reasoning.
- New generated tokens.

Even if one call is cheap, many repeated calls can add up.

# Caching

Caching can reduce API costs when the same input is sent repeatedly within a short time.

The provider may reuse part of the previous computation instead of charging the full input cost again.

**Same or repeated prompts do not affect costing in the usual full-price way because caching can make repeated input cheaper.**

Caching usually applies automatically in some systems, while other systems may require specific setup or prompt structure.

# Important Cost Catches

There are two important details to remember:

1. Input cost includes the full sequence passed into the model, not just the newest message.
2. Output cost may include hidden reasoning tokens for reasoning models.

This means cost can be higher than expected if the prompt is long, the conversation history is large, or the model performs a lot of reasoning.

# Context Window Examples

Different models have different context-window sizes.

Some models support hundreds of thousands of tokens.

Some models support around a million tokens.

A larger context window makes it possible to include more information in one request, but large prompts may also increase cost.

# Practical Tips

Keep these ideas in mind when using LLM APIs:

- Short prompts are cheaper.
- Long chat history increases input cost.
- RAG content increases input cost.
- Multi-shot examples increase input cost.
- Longer answers increase output cost.
- Reasoning models may have hidden output-token costs.
- Repeated prompts may be cheaper because of caching.
- Large-scale products need careful unit-cost planning.

# Key Idea

The context window is the model's working space for one request.

API cost is mostly based on how many input and output tokens are processed.

A model with a larger context window can handle more information, but using that space can also increase cost.

Caching helps reduce repeated-input costs, especially when the same prompts or prompt prefixes are used multiple times.
